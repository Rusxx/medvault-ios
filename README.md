# MedVault

**MedVault** — нативное iOS-приложение на SwiftUI для локального хранения медицинских документов, ведения персональной медкарты и просмотра сохранённой истории. Приложение принимает изображения и PDF, сохраняет оригиналы внутри контейнера приложения, извлекает доступный текст и отображает только информацию, которую удалось найти в исходном документе или которую пользователь добавил вручную.

> **Важно.** MedVault не является медицинским диагностическим инструментом и не предоставляет медицинских рекомендаций. OCR и извлечённые данные могут содержать ошибки; их необходимо сверять с оригиналом документа.

## Возможности

MedVault использует пять основных вкладок: главная страница, история, анализы, медкарта и приватность. Библиотека документов остаётся доступной из раздела истории; импорт и просмотр оригиналов сохраняют прежний поток работы.

| Раздел | Реализованная функция |
|---|---|
| Главная | Имя пользователя, счётчики документов, лекарств, аллергий и обработанных записей; быстрый импорт и переход к врачебному обзору. |
| История | Хронологическая Timeline документов, заболеваний, начала и окончания лекарств; поиск, периоды 7 дней, месяц, 6 месяцев, год, всё время и произвольный диапазон. |
| Анализы | Автоматическая группировка совпадающих показателей по нормализованному имени и единице измерения между документами. |
| Динамика | Экран значений показателя по датам, переход к исходным документам и линейный график для двух и более числовых значений. |
| Врачебный обзор | Компактный локальный свод пациента, активных заболеваний, текущих лекарств и последних анализов. Это отображение записей, а не диагноз. |
| Документы | Импорт фото/PDF, локальное OCR или извлечение PDF-текста, просмотр оригинала, статусы обработки, повтор, удаление и копирование текста. |
| Ручные правки | Исправление OCR-текста, названия, типа, клинической даты, врача, учреждения, анализов и локальных связей с заболеваниями и лекарствами. |
| Медкарта | Личные данные, аллергии, заболевания с датами и статусами, лекарства с датами начала/окончания и операции. |
| Экспорт | Формирование PDF выбранного периода истории во временном локальном файле и открытие системного листа передачи. |
| Приватность | Описание локального хранения, отсутствия регистрации, аналитики, рекламы, backend и внешних AI API. |

## История, анализы и связи

История строится локально из документов, дат заболеваний и дат начала/окончания лекарств. Поиск фильтрует заголовок и описание событий; период применяется к локальным датам событий. Пользовательский произвольный период включает полные календарные дни выбранных границ.

Структурированные показатели находятся внутри `ExtractedMedicalInfo.labValues` каждого документа и сохраняются в уже существующем локальном JSON документов. Для долговременного просмотра `ClinicalAggregationService` формирует наблюдения с датой, исходным документом, значением, единицей и референсным диапазоном. Одинаковые показатели объединяются только при совпадении нормализованного имени и нормализованной единицы; специальные русские и английские псевдонимы для гемоглобина, WBC и тромбоцитов также приводятся к общему ключу. Это локальная техническая группировка, а не медицинская интерпретация.

Сохранённый документ может быть связан с любым числом заболеваний и лекарств через их UUID. При сохранении формы ручного редактирования эти связи синхронизируются в обе стороны: документ хранит идентификаторы медкарты, а запись медкарты хранит идентификаторы связанных документов. При удалении документа локальные обратные ссылки очищаются.

## OCR, PDF и визуализация

Для изображений приложение использует `VNRecognizeTextRequest` из Apple Vision с языковыми настройками `ru-RU` и `en-US`, уровнем распознавания `.accurate` и коррекцией языка. Apple указывает, что обработка Vision для распознавания текста выполняется на устройстве; это соответствует локальному режиму приложения.[1] Консервативный локальный парсер выделяет только явно присутствующие дату, врача, учреждение, показатели, единицы, референсные значения, лекарства с дозировками и явно подписанные заключения. Он не подставляет отсутствующие значения и не формирует клинические выводы.

Для PDF применяется `PDFDocument`: текст извлекается из доступного текстового слоя, а первая страница используется для миниатюры и встроенного просмотра. PDFKit предоставляет модель `PDFDocument` и вид `PDFView` для работы с PDF в приложениях.[2] Сканированный PDF без доступного текстового слоя отмечается ошибкой обработки; для OCR такого документа его можно импортировать как изображение.

Новый экран динамики использует встроенный Swift Charts с `LineMark` и `PointMark`. Apple описывает Swift Charts как SwiftUI framework для создания настраиваемых визуализаций, включая линейные графики.[4] График является визуализацией сохранённых числовых значений по датам и не показывает норму, прогноз или медицинскую оценку.

Системный `PhotosPicker` используется для выбора фото из медиатеки, а пользовательский выбор обрабатывается через `PhotosPickerItem` и `Transferable`.[3] Импорт файлов выполняется через системный `fileImporter`; при захвате камеры запрашивается стандартное разрешение iOS.

## Локальный PDF-экспорт

Кнопка в разделе «История» создаёт PDF только для текущего отфильтрованного списка событий. Файл записывается во временную директорию приложения и передаётся в системный `UIActivityViewController`; MedVault не загружает его на сервер. В реализации используется `UIGraphicsPDFRenderer`, который Apple предоставляет для создания PDF-файлов и записи их непосредственно на диск.[5]

Экспорт содержит имя пациента, выбранный период, предупреждение о недиагностическом характере отчёта и строки истории. Он не включает оригиналы документов, не добавляет новые медицинские интерпретации и не является клиническим отчётом.

## Архитектура

Проект следует разделению SwiftUI/MVVM. `AppStore` — единый `@MainActor` view model, координирующий импорт, состояния обработки, повтор, удаление, ручные изменения, двусторонние связи и сохранение профиля. Сервисы изолируют ввод-вывод, OCR, PDF, локальную агрегацию анализов и PDF-экспорт.

```text
MedVault/
├── App/                              # Точка входа SwiftUI
├── Models/
│   ├── Models.swift                  # Codable-модели документов и медкарты
│   └── ClinicalModels.swift          # Timeline, диапазоны и агрегированные анализы
├── Views/
│   ├── TimelineView.swift            # История, поиск и фильтры периода
│   ├── AnalysesView.swift            # Список сгруппированных показателей
│   ├── AnalysisTrendView.swift       # График и значения по датам
│   ├── ClinicalOverviewView.swift    # Врачебный обзор
│   └── DocumentEditView.swift        # Ручные правки и связи
├── ViewModels/
│   └── AppStore.swift                # Импорт, локальная аналитика и синхронизация ссылок
├── Services/
│   ├── StorageService.swift           # Application Support + JSON metadata
│   ├── OCRService.swift               # Vision OCR
│   ├── PDFService.swift               # PDFKit extraction / preview
│   ├── MedicalTextParser.swift        # Только явные текстовые паттерны
│   ├── ClinicalAggregationService.swift # Timeline и группы показателей
│   └── HistoryPDFExportService.swift  # Локальный PDF export
├── Components/                        # Общие SwiftUI-компоненты
└── Resources/                         # Asset catalog и Info.plist
```

## Приватность и хранение

Оригиналы документов и JSON-метаданные записываются в `Application Support/MedVault` внутри контейнера приложения. Расширенные модели используют обратносуместимые optional-поля `Codable`, поэтому ранее сохранённые документы и медкарты продолжают декодироваться без миграционного backend. Приложение не содержит `URLSession`, Firebase, Alamofire, HTTP-клиента, учётных записей, рекламы или аналитики.

Поэтому экран «Конфиденциальность» достоверно сообщает: **«Ваши документы хранятся на устройстве. Приложение не отправляет медицинские документы на сервер.»**

Демонстрационная запись доступна только через меню на главном экране и всегда помечается **«Пример данных»**. В ней нет реальной медицинской информации.

## Требования

Для сборки необходимы macOS, современный Xcode с iOS 17 SDK или новее и доступный iOS Simulator. На реальном устройстве необходимо выбрать свою signing team в настройках target, если Xcode запросит подпись. В проекте не используются CocoaPods, Swift Package Manager или сторонние библиотеки.

## Запуск в Xcode

1. Клонируйте репозиторий и откройте `MedVault.xcodeproj` в Xcode.
2. В списке схем выберите **MedVault** и симулятор iPhone c iOS 17 или новее.
3. Нажмите **Run** (`⌘R`).
4. Импортируйте изображение или PDF с главного экрана.
5. Откройте вкладки «История» и «Анализы» для проверки Timeline, фильтров, группировки и графика. Используйте карандаш в деталях обработанного документа для проверки ручных правок и связей.
6. Экспортируйте отфильтрованную историю через кнопку системной передачи. Камера работает на физическом устройстве; в Simulator предусмотрено понятное уведомление о недоступности камеры.

## Сборка из Terminal

В macOS с установленным Xcode выполните:

```bash
xcodebuild \
  -project MedVault.xcodeproj \
  -scheme MedVault \
  -sdk iphonesimulator \
  -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  build
```

Если указанная модель симулятора отсутствует, замените `name=iPhone 16` на устройство из `xcrun simctl list devices available`.

## Ограничения MVP

MedVault не ставит диагнозы, не нормализует медицинские единицы между разными системами измерения, не оценивает результаты анализов и не прогнозирует динамику. График доступен только для двух и более числовых сохранённых значений показателя с одинаковым локальным ключом. OCR зависит от качества изображения, освещения, языка, шрифта и ориентации документа. PDF с текстовым слоем извлекается напрямую; PDF-сканы не проходят OCR в версии MVP.

Локальное хранение не заменяет резервное копирование устройства. Удаление документа из MedVault удаляет его оригинал из контейнера приложения и очищает локальные ссылки из медкарты. Экспорт создаёт временную копию выбранной истории; дальнейшая передача файла зависит от действия пользователя в системном листе.
